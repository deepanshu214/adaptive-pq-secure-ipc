==============================================================================
  PHASE 1 - IPC SECURITY ANALYSIS
==============================================================================

  IPC threat catalogue
  --------------------
  +---------------------------+--------------------+--------------------------------------------------------------------------------+----------------------------------------------------------------------------+
  | Threat                    | Violated property  | IPC attack vector                                                              | Countermeasure                                                             |
  +---------------------------+--------------------+--------------------------------------------------------------------------------+----------------------------------------------------------------------------+
  | Process impersonation     | Authentication     | Squatting on a socket path / pipe name / bus name, PID reuse, spoofed endpoint | Peer authentication: HMAC (L1), Ed25519 (L2-L3), ML-DSA (L4-L5)            |
  | Unauthorized access       | Access control     | World-readable shared memory, permissive message-queue ACLs, leaked handles    | Per-session keys: only authenticated peers hold the traffic key            |
  | Message tampering         | Integrity          | Writable shared-memory ring buffer, compromised broker, ptrace injection       | MAC / AEAD authentication tag on every message                             |
  | Replay attack             | Freshness          | Recorded socket traffic replayed by a local attacker                           | Monotonic sequence numbers, sliding replay window, periodic re-keying      |
  | Eavesdropping             | Confidentiality    | Debug interfaces, /proc inspection, broker logs, side channels                 | AEAD encryption (AES-256-GCM) with ephemeral session keys                  |
  | Harvest-now-decrypt-later | Quantum resistance | Exfiltrated captures of long-lived sensitive IPC traffic                       | ML-KEM (FIPS 203) key establishment, ML-DSA (FIPS 204) signatures, AES-256 |
  +---------------------------+--------------------+--------------------------------------------------------------------------------+----------------------------------------------------------------------------+

  Quantum threat model
  --------------------
  Shor's algorithm breaks X25519 / Ed25519 / RSA; Grover halves symmetric key
  strength (AES-256 keeps ~128-bit). Mosca's inequality x + y > z decides
  harvest-now-decrypt-later exposure with y = 5 years (migration) and z = 15 years (time to a
  cryptographically relevant quantum computer): data that must stay secret for
  more than 10 years needs quantum-safe key establishment today.
